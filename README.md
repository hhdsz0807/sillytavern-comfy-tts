## 🌟 核心特性与架构升级

### 1. 🎨 内置原生 ComfyUI 高阶工作流引擎
- **文生图 + 链式多 LoRA + 高清潜空间放大（Hires Fix）**：
  - **动态模型链式装载**：根据当前角色或情景命中规则，自动在 `CheckpointLoaderSimple` 之后级联多个 `LoraLoader` 节点，平滑传递 `MODEL` 与 `CLIP` 管道（常驻 LoRA 无条件全量优先装载；**动态角色 LoRA 每张图严格只激活 1 个**，即使正文出现 1girl/1boy 双主体也绝不挂两个角色 LoRA，杜绝特征词串台导致的画风劣化与权重污染）。
  - **智能特征词注入**：正文或标签中检测到角色 LoRA 关键词时，自动挂载对应 LoRA，并将配置的**角色特征触发词**精准注入到正向提示词中。
  - **潜空间二次放大 (Hires Fix)**：支持开启 `LatentUpscaleBy` + 二次 `KSampler` 重绘，放大倍数（1.1x ~ 2.0x）与重绘幅度（Denoise: 0.2 ~ 0.75）在面板中可精细微调，大幅提升画面细节与精细度。
- **直连 ComfyUI 原生引擎**：直接与标准 ComfyUI 服务（默认 `http://127.0.0.1:8188` 或远程局域网 IP）通信，无需任何代理或桥接程序。
- **自动探查资产与算法**：点击按钮即可自动从 ComfyUI 端点探查已安装的 Checkpoint 模型、LoRA 权重列表、采样器（Sampler）与调度算法（Scheduler），并在面板中以下拉列表呈现。
- **WebSocket 实时步数与进度推送**：通过 ComfyUI 原生 WebSocket 通道实时监听采样步数与执行进度（百分比与执行节点实时反馈），并辅以 `/history` 轮询双重兜底。

## 🧩 多后端对接（v2.1.0 新增：编辑 / MOSS 文生图 / H3 图生视频）

插件不再只有一套 SDXL 文生图，现在按**任务类型**各自对接本机 ComfyUI 里那套最合适的工作流。
三份工作流模板都是从本机 ComfyUI **真实跑通的提交**里导出的固定图，插件只改写
提示词 / 源图 / 种子 / 步数 / 尺寸几个字段，不在浏览器里重拼节点。

| 任务 | 入口 | 走哪套工作流 | 备注 |
| :--- | :--- | :--- | :--- |
| **文生图（原行为）** | 卡片里的 🎨 / `image###` 标签 | 插件内置 SDXL 工作流 | 支持多 LoRA 链、Hires Fix、外部 VAE |
| **文生图（可选）** | 设置里把「文生图后端」切到 MOSS | 本机 `MOSS-Image` 工作流 | 把中文写进画面最准；**不挂 LoRA**，尺寸必须是 16 的整数倍 |
| **图像编辑** | 图片卡片底栏 **✏️ 编辑** | 本机 `Qwen-Image 2.1` 编辑工作流 | 源图默认是卡片当前这张，也能从手机相册选；写中文指令即可（例：把头发改成亮粉色，其他别动） |
| **图生视频** | 图片卡片底栏 **🎬 视频** | 本机 `MiniMax H3` 二采工作流 | 输出 24fps + AAC 双声道；**6 秒≈7 分钟**，15 秒要 20 分钟以上 |

### 源图是怎么进去的

1. 点 ✏️ / 🎬 → 弹窗里确认源图（默认卡片当前那张，或点「📁 从手机相册选一张」）；
2. 插件把源图 `POST /upload/image` 传进 ComfyUI 的 `input` 目录（文件名 `sct_src_<时间戳>.png`）；
3. 把文件名塞进工作流的 `LoadImage` 节点，再 `POST /prompt` 提交；
4. 轮询 `/history/<promptId>`：编辑出图后作为**新卡片**追加（原图不动）；视频出片后渲染成 `<video>` 播放卡，带「⬇️ 保存到手机」。

### 结果去哪了（不会白跑）

- 编辑出的图会存进手机本地图库（IndexedDB），服务器 output 被清了也能看；
- 编辑卡 / 视频卡会写进**酒馆消息 extra**（`sct_backend_cards`），刷新或切聊天回来照样在；
- 视频文件同时留在 ComfyUI 的 `output/video/SCT_H3/` 下（默认文件名 `minimax_xxxxxxxx-audio.mp4`）。

### 🎬 视频提示词可以交给聊天模型自动写（v2.2.0）

不用自己憋英文六段式了：让**酒馆主模型**在写正文和生图标签时，顺手把视频提示词也写出来。

- **开关**：设置 → 「自动配图指示与消息交互」→ **「🎬 让聊天模型在写生图标签时，顺手写视频提示词」**（默认开）
- 开启后模型每插一个 `<image>` 标签，就在**它后面**补一个 `<video>六段式</video>`：
  - 正文里显示成一枚 **「🎬 视频提示词已就绪」** 小徽章，不会污染正文（点它没用，得点卡片上的按钮）；
  - **按位置配对**：谁的图标签**紧后面**跟着视频标签，就算谁的（所以模型只给其中某几张写了也不会张冠李戴；写在所有图之前的会谁的都不挂，退回默认模板）；
- 点图片卡片上的 **「🎬 视频」** → 弹窗**自动填进模型写好的那份**，你可以当场改；想退回默认模板点 **「↩️ 换成设置里的默认模板」**；
- 模型针对某一幕写的提示词是**场景专属**的，**不会**覆盖设置里的全局默认模板；只有你自己把「默认模板那条」改过并提交，才会记成新默认；
- **三档详略（v2.9.0 起镜头不再强制静止；v2.12.0 默认改成"以正文为剧本"）**：
  - `精简版`：1 个镜头 + 轻微推近/跟随，≤350 英文词（3~6 秒）；
  - `完整版`：2~3 个镜头、允许推拉摇跟，≤900 词（10~15 秒）；
  - `自由发挥`（**默认**）：**以正文为剧本，AI 自己拆 2~5 个镜头**，把角色动作、台词、运镜全设计出来，≤700 词（推荐 15 秒）；
- **镜头规则（v2.12.0 调整）**：**正文是剧本，参考图只当"人物长相 / 服装 / 场景 / 画风"的身份锚** —— 分镜、镜头、角色动作、台词都由 AI 根据正文决定；可以换景别、换角度、跟拍、让角色在场景里走动。底线只有三条：同一个人物、同一套画风、不出现第二个角色（不出现文字/水印）。
- **台词规则（v2.9.0 新增）**：正文里这个角色**说了话**，就把那句台词**原样**写进对应镜头（双引号、语言跟正文一致，**中文台词就写中文**），并写明 `she says it aloud with natural lip movement, the line is clearly heard in the audio`；正文没台词就不许编。

**🔊 让角色念出正文里的对话（v2.11.0）**

插件会**自动从正文里抓台词**（中文引号 `「」` `『』` `“”` 和英文双引号都认，最多 3 句、每句 ≤120 字），然后：

> **台词归属（v2.12.3 最终口径）**：**以 `<image>` 标签为界**——
> 上一张图的标签结束 → 这张图的标签开始，**中间这一整段正文就是这张图的正文**，从中取引号对话；
> 图片**后面**的文字属于下一张图；也**不会**往上一张图之前翻。
> 所以「图一 … 图二 … 图三」这样一条消息，图二只吃"图一标签到图二标签之间"那段正文里的台词。
> 这段里没有引号台词就显示"没识别到"，不兜底。

1. **🎬 弹窗里直接显示**：`🔊 让角色念出正文台词 — 本条识别到 2 句：我回来了。／今天好累啊。`（开关默认**开**）；
2. **看图重写时**：把这几句作为 **【★ 必须让角色说出来的台词】** 硬性塞给 AI —— 要求**原样引用**（不许改写/翻译/加戏）、放进最合适的镜头、写 `natural lip movement` 和音轨；
3. **不重写也生效**：提交时如果提示词里没有这几句，会自动追加一条
   `Spoken line (she says it aloud with natural lip movement; the line is clearly heard in the audio): "我回来了。" / "今天好累啊。"`；
4. 不想让角色说话就把弹窗里那个 🔊 开关关掉（做纯动作片时用）。

> 抓台词只认"引号里的内容"。如果你的正文用 `她说：xxx` 这种不带引号的写法，那抓不到 —— 要么让 AI 加引号，要么在弹窗里手动把台词补进提示词。

**📐 想换掉内置的分镜写法？现在可以自己写（v2.10.0）**

设置 → 多后端 → **「📐 分镜 / 写作规则」**：

- **留空** = 用内置那套（跟着「详略」档位走：精简 1 镜 / 完整 2~3 镜 / 自由发挥 3~5 镜，含"首帧与参考图一致 + 允许运镜 + 台词原样演"）；
- **填了就整段替换内置规则** —— 你想用"分镜表 / 镜头编号 / 时长"那种写法，直接写进去，模型会照它写；
- 两个按钮：**「↩️ 填入内置规则（当模板改）」**（把当前档位的内置规则灌进框里，在它基础上改）、**「🧹 清空（回到内置）」**；
- ⚠️ `<video>…</video>` 这个**标签格式由插件固定**（靠它认出视频提示词），自定义规则里不用写、也别改；
- 同一份自定义规则也会喂给「🧠 看图重写」，两处口径一致。
- 认得的写法：`<video>…</video>`、`&lt;video&gt;…&lt;/video&gt;`、`video###…###`（外面有 `<pre><code>` 包裹也照样认）。

> ⚠️ **代价要说清**：这会让**每条回复明显变长、多花 token**（每张图多 200~350 词英文）。不想花就关掉开关，回到"用设置里的默认模板 / 手写"；或者先只开精简版观察一阵。

### 🧠 让主模型"看着图"重写六段式（v2.4.0）

**问题**：让聊天模型在写生图标签时顺手写的视频提示词，是**在图片生成之前**写的 —— 它没看过图，所以最容易犯的错是**自己规定镜头**（medium shot / close-up…），结果出片"换角度、重新构图"；人物外观也可能和实际生成的图对不上。

两条对应修法（都已内置）：

1. **主模型写的时候就先禁掉**：注入的规范里加了一条「★★ 最重要 · 绝对不许自己定镜头」，并强制它写死 *The camera framing, angle, crop, composition, pose and background stay exactly the same as the reference image `<Picture 1>`… the camera never moves and the shot is never re-framed.*；人物外观不确定的一律写 `as shown in <Picture 1>`，不许编。默认模板也删掉了 `[Shot 1] Medium shot` 这类景别词。
2. **出图后可以再让主模型看图重写**：🎬 视频弹窗里新增 **「🧠 让主模型看图重写」** —— 把**这张图**连同当前聊天上下文一起发给酒馆主模型，让它按"实际看到的画面"重写一份六段式，结果**直接填进提示词框**（不写进聊天记录）。

**🧭 中文指导（v2.4.1）**：弹窗里提示词框**上面**还有一行「🧭 中文指导（可选）」—— 直接用中文写你想要的画面/动作，例：`她坐在窗边慢慢转头看向你` / `把外套脱掉后轻轻转个身`。点「🧠 让主模型看图重写」时，这句话会作为**硬性要求**一起发给主模型；人物可以动，但**镜头依旧不许动**（冲突时以镜头不动为准）。没点重写就直接开始，插件会先问一句"要不要先按中文指导重写再生成"，不会偷偷多花一次模型调用。

用的是什么上下文（v2.4.3 起更明确）：

| 会带上 | 说明 |
| :--- | :--- |
| **这条消息的正文** | 插件直接从界面上抓出来，作为【这一幕的正文】**显式**写进要求里——**不受聊天上下文截断影响**，老消息里的图也一样带得上 |
| 之前的对话 / 角色卡 / 世界书 / 对话预设 | 由酒馆的 `generateQuietPrompt` 正常构建（会和你在输入框发消息一样） |
| 这张图 | 以 Base64 内联发给模型 |

> 抓正文时会自动剔掉 `image###…###`、`<image>`、`<video>` 和我们自己的小徽章文字，只留叙事文字（超过 1200 字会截断）。

**🔌 走「独立 API」而不是酒馆配置（v2.7.0）**

不想动酒馆的连接配置、或者酒馆主模型不支持看图时，把「🧠 看图重写走哪个接口」切成 **「走独立 API」**：

| 字段 | 说明 |
| :--- | :--- |
| **API 地址** | OpenAI 兼容的 `…/v1/chat/completions`（**留空就复用设置里「AI 辅助」那个地址**） |
| **API Key** | Bearer Key（留空复用「AI 辅助」的 Key） |
| **🔗 连接并获取模型**（v2.8.0） | 用上面的地址 + Key 请求一次 `GET …/v1/models`，把**该接口返回的模型清单灌进下拉**；选一个就自动填进「模型」框。清单会记住（关掉弹窗再打开还在）；有的中转不带 `/v1` 前缀，插件会再退一步试 `…/models` |
| **模型名** | 必须支持看图，如 `gpt-4o` / `claude-*` / `qwen-vl-max`；接口不提供 `/models` 时直接手填 |

- 这条路径**完全不动酒馆的 API / 连接配置**，只发一次带图的 `chat/completions` 请求；
- **预设仍然用酒馆已有的**：插件会读该预设的 `temperature` / `top_p` 带过去；
  ⚠️ 预设里的**提示词模板属于酒馆内部管线**，外部接口用不上——这点如实说明，不是漏做；
- 失败会明确报错（HTTP 码 + 接口返回的 message），不会静默失败；
- 走「酒馆主模型」时仍然是原来的行为（预设/提示词模板完整生效，需要模型支持看图 + 媒体内联开启）。

**🎛️ 走「酒馆主模型」时可以选这些（v2.6.0 起；v2.8.1 删掉了多余的「模型」控件）**：

| 控件 | 数据来源（都是酒馆里**已经保存**的） | 行为 |
| :--- | :--- | :--- |
| 🧠 重写用「**连接配置**」 | 酒馆「连接配置 / Connection Profiles」里保存的条目（`extensionSettings.connectionManager.profiles`） | 选它就等于换掉这一份配置里的 **API + 地址 + 密钥 + 模型**；下拉显示「配置名 · 它存的模型」——**模型就用配置里那个，不用再单独选** |
| 🧠 重写用「**对话预设**」 | 酒馆已保存的 Chat Completion 预设（**显示预设名**；酒馆内部的值是序号，插件会自己换算） | 留空 = 跟随当前；选了只影响这一次 |

- 切换顺序：**连接配置 → 预设**；还原是**逆序**，全部写在 `finally` 里——**包括报错也会还原**；
- 两个选择都会记住（`comfyRewriteProfile` / `comfyRewritePreset`，预设记的是**名字**）；
- 读不到清单时会显示提示并自动跟随当前设置（常见原因：**「连接配置」扩展没启用**，或酒馆版本较旧）。

用的是酒馆自己的 `generateQuietPrompt({ quietPrompt, quietImage })`：

- ✅ **带当前角色卡 + 当前对话预设/提示词管理器**（就是"在输入框里发这句话"的那套上下文）；
- ✅ 走**安静生成**，不会往聊天里塞一条 AI 消息；
- ✅ 图用 Base64 内联发过去；

**前提（不满足就是白发，模型看不到图）**：

| 条件 | 怎么看 |
|---|---|
| 用的是**聊天补全(openai 兼容)**接口 | 不是文本补全；插件会自动探测并提醒 |
| 酒馆里 **媒体内联 (Media Inlining)** 开着 | 设置 → 聊天补全；DOM 上是 `#openai_media_inlining` |
| **模型本身支持看图** | GPT-4o / Claude / Gemini / Qwen-VL 这类；纯文本模型不行 |
| 酒馆版本有 `generateQuietPrompt` | ≥ 1.12 左右；本机源码核对为 **1.19.0**（`public/scripts/st-context.js` 里有导出） |

不满足时插件会弹确认框说明原因，你可以选择"仍然重写"（那就等于让它凭当前剧情文字重写，效果等同于"写的时候禁掉镜头"那条）。

### 🎬 一采先出、二采后补（v2.3.0）

MiniMax H3 是两遍跑的：**一采**先出一版低清草稿、**二采**再出高清带音轨的成品。**本机 3 秒测试实测：一采 258 秒就出片，二采 717 秒才出 —— 中间差了 7 分 39 秒**（长片差距更大）。

所以现在不是"等一条跑完才给你看"，而是：

- **一采一好就推**：卡片上立刻出现「一采 · 低清草稿」那条视频，可以先看构图、动作对不对；
- **二采好了再补**：紧接着追加「二采 · 成品（高清 + 音轨）」那条，两条都在同一张卡里，各自的「⬇️ 保存到手机」按钮分开；
- 卡片顶部有一行状态（`一采已出（低清草稿），二采成品还在跑…` → `一采 + 二采 都已出片 ✅`）；
- 推送依据是 ComfyUI 的 **WebSocket 逐节点 `executed` 消息**（不是等 `/history` 全部跑完）；
- 跑的过程中卡片上有 **「🛑 中止本次视频任务」**；**万一二采失败，一采草稿会保留**；
- 两条视频文件名都带**唯一时间戳**并分目录：`output/video/SCT_H3/一采/…` 与 `output/video/SCT_H3/二采/…`。

**只想快速看个草稿？勾上弹窗里的「只跑一采（不跑二采）」（v2.4.2）**：

- 勾选后提交的工作流会**直接摘掉二采输出节点**，ComfyUI 只执行一采那条链（省掉一次 4 步精修 + 3D 潜空间放大）；
- 好处：**快很多、显存更省**；代价：只有一采的草稿画质，**没有**二采的高清成品；
- 勾选状态会记住（存 `comfyVideoOnePassOnly`），下次打开弹窗保持；
- 卡片上那条视频会标注「一采 · 草稿（本次只跑一采，没有二采高清版）」，状态行写「一采出片完成（本次没跑二采）」。想升级画质就取消勾选再跑一次。

### 排障

| 现象 | 原因 / 处理 |
| :--- | :--- |
| 编辑/视频卡在「正在把源图上传到 ComfyUI」 | ComfyUI 地址不通（手机端多半是 Cloudflare 隧道换域名了）→ 回设置里重填地址并点「📡 测试与扫描」 |
| 提示 `提交失败：…` 且带节点号 | 本机那套工作流的节点/模型被改过（换过模型文件名、删过插件）→ 在 ComfyUI 里打开对应工作流确认能跑 |
| **先生图再点视频，要不要手动清显存？** | **不用。** 本机 ComfyUI 是动态显存：模型按需流式进显存、用完即放（日志里 `prepared for dynamic VRAM loading … Staged`），视频链还有 `force_unload: true` 主动吐显存（日志 `[MinimaxH3-3D] ✅ Model offloaded to CPU. VRAM released.`）。实测「图片 → 视频 → 图片」连跑 **零 OOM**。想更保险：弹窗里点 **「🧹 腾显存」**（等价 `POST /free`，本机实测一次释放约 3.9GB）。真正的瓶颈是 **16GB 内存**（视频文本编码器 25.9GB + 主模型 20GB 要流式过一遍），跑视频前建议关掉浏览器等大内存程序 |
| **更新插件后，老消息上的「✏️ 编辑 / 🎬 视频 / 立即开始生图」点了没反应** | 已修（v2.6.1）：卡片按钮改成**聊天区统一委托**（在 `#chat` 上用捕获阶段装一次），不再依赖"每次渲染把事件绑到按钮上"。所以不管卡片是哪一次渲染出来的、页面更新后 DOM 有没有被重刷，点了都能用；真点不动时会弹一句提示（比如"图片信息丢了，请重新生成"），把那句提示发我就能定位 |
| 视频跑很久没动静 | 正常：6 秒片约 7 分钟，15 秒要 20 分钟以上；进度条只在采样阶段刷新 |
| **别的角色卡 / 以前生成的图串到这条消息上** | 已修（v2.1.4）。根因：老版本给 ComfyUI 的文件名前缀是固定的 `SillyTavern`，而 ComfyUI 的编号计数器**每次重启或清空输出就归零** → 新图会**覆盖同名的旧文件**；老会话的卡片里存的还是那个文件名，于是刷出别人的图，手机本地图库按文件名缓存又会再串一遍。<br>现在三道闸：① 每次出图都用**唯一文件名前缀**（时间戳+随机：`SillyTavern_<戳>_` / `SCT_MOSS_<戳>_` / `SCT_EDIT/QW21_<戳>_` / `video/SCT_H3/minimax_<戳>_`）；② 从缓存恢复、以及显示手机本地副本之前都**核对提示词**，对不上就不显示；③ 删掉了**没有聊天作用域**的旧键名兜底（那是跨聊天直接命中的口子）。<br>⚠️ 老消息里被覆盖掉的图**无法找回**，需要就点卡片「🔄 重新生成」；本地缓存里可能还存着串掉的图，可在设置 → 生成图片管理里点 **「🧹 清空手机本地图库缓存」** |
| **编辑/视频弹窗被酒馆界面盖住、或关不掉** | 已修（v2.1.2 / v2.1.3）：弹窗改用原生 **`<dialog>.showModal()`**，会进浏览器的**顶层（top layer）**，无论酒馆 UI / 主题 / 其它插件把 z-index 定多高都盖不住它；关闭入口 4 条：顶栏「✕ 关闭」、底部「✖ 关闭（不生成）」、点暗色背景、桌面按 Esc。若 `showModal` 不被支持会自动退回普通浮层（z-index 顶到 `2147483647`）并弹提示 |
| **编辑出来的图和原图几乎一样** | ★ 两个原因，都已在本机实测定位：<br>① **CFG 太低**：工作流存档里是 1.0，此时出图与源图像素差只有 ≈1（发色根本不变）；<br>② **加速节点**：`TESpeedQwenImage21` 挂在模型链上时，即便 CFG=4 也几乎不改图。<br>所以插件内嵌的编辑模板**已把加速节点摘掉**（`QwenImage21Cache.model` 直接接 `UNETLoader`），并把默认改成 **steps=30 / CFG=4.0**；实测像素差 ≈5.6（对比 CFG=1 的 ≈1）、头发明显变粉。想更快可以把 CFG 调回 1 试试，但那时基本不会改图 |
| 视频卡没了但文件在 | 点「🧩 本次工作流」看不到就说明记录被清了；直接去 ComfyUI 的 `output/video/SCT_H3/` 取文件 |
| MOSS 出图报 `Not a complete moss-image diffusion model` | 模型目录填错/不完整（要含 `transformer/ text_encoder/ tokenizer/ vae/` 四个子目录） |

## ⚙️ 原生酒馆配置面板参数详解

在酒馆右侧抽屉 **Extensions Settings** 或顶部魔杖菜单中展开 **ComfyUI 绘图 & TTS 语音朗读**：

| 配置板块 | 参数项 | 说明 |
| :--- | :--- | :--- |
| **ComfyUI 服务与模型** | ComfyUI 服务地址 | ComfyUI 原生 API 端口，默认 `http://127.0.0.1:8188` |
| | 生图工作流 | 可选：标准文生图 / 文生图+多LoRA / 文生图+多LoRA+高清放大 (Hires Fix) |
| | Checkpoint 模型 | 支持手动输入或点击「测试与扫描」后从下拉框一键选择 |
| **多 LoRA 规则管理** | 添加/删除 LoRA 卡片 | 可无限添加角色 LoRA，独立开关启用/禁用、常驻生效 |

| | 激活关键词 | 正文或提示词包含此关键词时（如 `柚木凪, 银发`），自动激活挂载 |
| | 角色特征激活词 | 激活时自动组合进正向提示词（如 `nagi, 1girl, silver hair...`） |
| **质量词与尺寸** | 固定正向质量词 | 默认 `(masterpiece, best quality, highly detailed), ` |
| | 画风后缀提示词 | 默认 `, 8k, photorealistic, cinematic lighting` |
| | 通用负向提示词 | 默认去畸变、坏手、低画质负向词库 |
| | 图像尺寸 | 提供 `512x768`、`768x1024`、`1024x1024`、`768x512` 快捷芯片与自定义宽高 |
| | 单次生成张数 | 1 ~ 3 张（生成后在卡片中手势滑动轮播） |
| | 采样步数与 CFG | 默认 20 步、CFG 7.0，采样器与调度算法下拉可调 |
| **高清潜空间放大** | 放大倍数 (Hires Scale) | 1.1x ~ 2.0x 潜空间双三次插值放大 |
| | 重绘幅度 (Denoise) | 0.2 ~ 0.75，推荐 0.45 保持主体一致并增加高频细节 |
| **配图指示与消息交互**| 自动生图开关 | 自动拦截消息中的 `<image>` 标签并立即启动后台渲染 |
| | 上下文自动注入 | 自动向提示词流末尾注入标准配图提示词模板 |
| | 复制配图指示 | 一键复制完整指令文本，方便导入到世界书或角色卡 |
| **TTS 语音朗读** | 引擎类型 | 小米 MiMo 在线 TTS / Web Speech API / OpenAI 兼容接口 |
| | 小米 MiMo 配置 | API Key、三款模型选择、内置音色（冰糖/茉莉等）、唱歌模式开关、音色设计 Prompt、声音克隆 Base64 |
| | 发音人与调节 | 本地发音人枚举选择、语速（0.5x~2.0x）与音调（0.5~1.5）平滑调节 |

## 📦 安装与部署

### 电脑端 / 手机端 SillyTavern 纯净安装
直接克隆或下载解压至 SillyTavern 的第三方扩展目录：

```bash
cd <SillyTavern安装目录>/public/scripts/extensions/third-party/
git clone https://github.com/hhdsz0807/sillytavern-comfy-tts.git
```

目录层级结构：
```text
SillyTavern/
└── public/
    └── scripts/
        └── extensions/
            └── third-party/
                └── sillytavern-comfy-tts/
                    ├── manifest.json
                    ├── index.js
                    ├── style.css
                    └── README.md
```

完成后刷新酒馆浏览器页面，插件将自动完成加载并生效！

## 💡 使用指南与快捷指令

### 1. 自动配图
只需保持配置面板中的「自动向 AI 上下文注入【自动配图指示】」开启，AI 在生成精彩情节时便会输出：
```text
<image>image###sfw, 1girl, emilia \(re:zero\), silver hair, long hair, purple eyes, white flower hair ornament, purple and white dress, elf ears, standing in sunlit mansion hallway, gentle smile, looking at viewer###</image>
```
插件会即时捕获该标签，将其渲染为优雅的轮播卡片，并向 ComfyUI 提交渲染任务。

### 2. 手动与快捷操作
- **消息工具栏生图**：点击消息右下角的 `🎨` 图标，输入任意自定义提示词即可为当条消息生成配图。
- **斜杠命令生图**：在对话输入框中输入 `/comfy 1girl, masterpiece, city night` 即可快速出图。
- **划选朗读**：长按或鼠标拖动选中任意聊天段落，点击弹出的 `🔊 朗读选中文字` 胶囊。
- **整条消息朗读**：点击消息右下角的 `🔊` 图标，支持随点随停。
- **斜杠命令朗读**：输入 `/tts 想要朗读的文本`。
